# PathForge AI security audit

Audit date: **25 October 2026 (Asia/Kolkata)**. Baseline: local Git commit `c5e4c29`, plus the working changes described here. Scope: FastAPI routes/services/schemas, SQLAlchemy models/migrations/seeding, Next.js pages/components/clients/browser storage, optional AI boundary, authoring/submission scripts, dependency locks, CI and deployment configuration. No public deployment or external host was tested; none is claimed. This is a repository review and automated regression assessment, not a penetration-test certification.

References: [OWASP Top 10:2025](https://top10.owasp.org/2025/) and [OWASP API Security Top 10:2023](https://api-security.owasp.org/editions/2023/en/0x11-t10/). Frontend nonce implementation follows the [official Next.js CSP guide](https://nextjs.org/docs/app/guides/content-security-policy). These are awareness frameworks, not a guarantee that passing a checklist establishes security.

## Threat model and existing controls verified

Unauthenticated guests intentionally read public catalogs, calculate stateless matches/plans, take practice quizzes and optionally request AI wording. There are no server-side student accounts, stored student profiles, private roadmap URLs or authenticated student ownership endpoints. Public catalog IDs are not authorization credentials. An expert's ID never grants administrative access.

The single administrator uses a backend-only bearer token. Inspection found existing server authorization on all four expert administration operations, constant-time token comparison, disabled administration without configuration, private contact redaction, explicit CORS origins, Pydantic validation, parameterized ORM queries, React text rendering, trusted HTTPS learning-resource links, and schema-validated AI fallback. No working authentication bypass, public write route, exploitable SQL injection or exposed real credential was found in the examined source. This is a finding within the reviewed scope, not proof of absence.

New tests enumerate the actual OpenAPI administration inventory and exercise every operation without authorization. Known expert IDs, forged roles/JWTs/cookies/query tokens, Basic authentication, oversized/duplicate bearer headers, middleware-bypass headers and cross-origin attempts do not grant access. Actual database records remain unchanged after denied mutations. Students cannot set expert approval flags through a public endpoint. Legitimate administrator CRUD, publication gates, quiz grading, matching, progress and Marathi UI remain covered by the original regressions.

## CSRF and prompt injection

Admin authentication uses an explicit Authorization header, not ambient cookies. Browser clients now explicitly omit cookies. Cross-origin pages cannot obtain the bearer token through the intended flow; CORS permits only configured origins, and the server additionally rejects foreign/null Origin values on administrative calls. Cookie/query/forged-role negative tests fail authorization. A non-browser caller may omit Origin but still must supply the secret: Origin is defense in depth, not authentication. Introducing cookie sessions later requires CSRF tokens, appropriate SameSite settings and a new review.

Student free-text study area is excluded from provider prompts. The new prompt-injection regression sends an explicit instruction attack and verifies it never reaches the provider; unknown `system_prompt` input is rejected. Selected skills/interests must be catalog values. Existing regressions reject fabricated resources/tasks, duplicates, extra score fields, HTML/links, oversized prose, quota/timeout and malformed provider envelopes. AI has no tools, SQL authority or ability to mutate the plan. Regex/schema checks cannot establish factual correctness or eliminate every semantic prompt attack; the UI keeps wording advisory and original calculations authoritative. No live provider key or paid call was used.

## Dependency and secret scanning

On this audit date the passing scans reported **zero known advisories** for npm frontend (203 resolved packages), root npm (no external dependencies), Python runtime/test lock (34 packages), pitch-authoring lock (5), and isolated security-tool lock (33). This does not establish that dependencies are free of undisclosed vulnerabilities. No application dependency version upgrade was required by these results; `defusedxml==0.7.1` was added for the XML boundary.

Bandit passes the medium/high severity gate. Reviewed low-severity warnings concern `subprocess` in the local secret scanner: it uses fixed Git argv, no shell, and does not accept a command string from the application. They are retained, not silently claimed fixed. The old XML findings are covered by passing negative tests.

Secret scanning found no unreviewed candidate in current tracked/unignored text or the one currently reachable baseline commit. Four exact false-positive fingerprints are reviewed in `scripts/security-secret-allowlist.json` (one fake redaction sentinel and three public deterministic task IDs). Generated manifest checksum fields are separately recognized; tests ensure this cannot exempt an API-key field or another path. Scans report locations/fingerprints only and do not submit candidate values for provider verification. Gitignored local environments/databases and binary images/video/PPT/PDF/ZIP contents are outside automated text scanning; private operational secrets must remain outside version control. Removed/unfetched Git objects are outside reachable-history coverage. Scan all fetched refs before publishing.

### Reproduce locally

From the repository root, Windows PowerShell:

```powershell
backend/.venv/Scripts/python.exe -m venv .tools/security-venv
.tools/security-venv/Scripts/python.exe -m pip install -r scripts/security-requirements.txt
npm.cmd run security:scan
$env:PLAYWRIGHT_CHANNEL='msedge'
npm.cmd run check:e2e
npm.cmd run submission:test
```

On Linux/macOS use `python3 -m venv .tools/security-venv`, `.tools/security-venv/bin/python -m pip install -r scripts/security-requirements.txt`, and `npm` instead of `npm.cmd`. Use installed Playwright Chromium rather than the Edge channel. Normal application dependencies must already be installed as documented in README. Security tools are isolated from the runtime environment. The scanner checks advisory services over the network and fails on scanner/network errors rather than presenting an incomplete check as clean.

Local full reports are in ignored `.test-tmp-security/latest/` and test logs in `.test-tmp-security/`. `summary.json` contains tool exit status and UTC timestamp. Review potential-secret or static-analysis reports privately. CI runs the same scan gate on push/PR and weekly; no live service credentials are required. Scan findings fail the job at any npm/pip advisory severity, any unreviewed secret, or Bandit medium/high severity.

## Deployment requirements and residual risks

1. Install the updated backend lock and apply `alembic upgrade head` before serving. Migration `0004_security_quotas` adds only quota counters; it must not erase catalog/expert data. Missing/unavailable quota storage denies paid AI calls.
2. Set `ENVIRONMENT=production`, `ALLOWED_HOSTS=["actual-api-host.example"]` and `CORS_ORIGINS=["https://actual-frontend.example"]` in backend configuration. Replace the examples with real exact hosts/origins. Production defaults intentionally fail until configured. Public docs remain disabled unless explicitly enabled with `EXPOSE_API_DOCS=true`.
3. Set frontend `NEXT_PUBLIC_API_URL` to the actual HTTPS API origin. It must contain no key, userinfo, path, query or fragment. HTTP is accepted only for loopback development. Keep both `ADMIN_TOKEN` and `AI_API_KEY` exclusively in backend secrets.
4. Generate `ADMIN_TOKEN` with a cryptographic generator, e.g. `python -c "import secrets; print(secrets.token_urlsafe(48))"`, and store it privately. Random ASCII bearer values of 32–256 characters are required; length/character checks do not prove entropy. Rotate after exposure and update/restart every worker. A shared bearer token provides no per-operator account, MFA, expiry or individual revocation. Place real administration behind an identity-aware gateway/access restriction; use individual authenticated roles before expanding the operator team.
5. **Use durable shared database storage before retaining expert contacts or enabling paid AI.** Render Free's ephemeral SQLite default cannot retain contacts or quota counts across filesystem replacement; deleting/recreating the database resets budgets. All workers must share the same database. This audit exercised SQLite, including reconnection/concurrency. PostgreSQL needs a compatible installed/locked driver and separate target verification; no PostgreSQL deployment is claimed.
6. AI quotas now use atomic fixed UTC windows (5/minute, 100/day defaults). Minute-boundary bursts are possible; these are request counts, not a monetary spending cap. Configure provider-side quotas/billing controls. Guests can consume the shared allowance and force fallback for others. General API/auth-failure limits remain process-local and reset/multiply across workers; enforce shared edge limits, per-client fairness and bot controls before scaling.
7. Require HTTPS at the actual frontend/API ingress, trusted host routing, request/header size limits, slow-connection timeouts, concurrent-connection limits and upstream DDoS controls. The supplied server ignores forwarded identity headers. HSTS headers are present in production paths, but actual hosted TLS, network restrictions and host configuration remain untested. CORS is not an authorization boundary against non-browser callers.
8. Nonce CSP makes all pages dynamic and uncacheable as HTML/RSC; do not replace this with static export or shared cached HTML containing stale nonces. Immutable Next assets may remain cached. This increases SSR work compared with the earlier static frontend. Inline **style attributes** remain allowed for existing progress indicators; executable inline scripts remain blocked. Trusted application scripts, compromised dependencies/extensions or a stolen nonce are outside CSP's guarantees.
9. Restrict database/filesystem access and encrypt backups; expert contact data may be personal. Browser profiles and quiz badges are not encrypted/authenticated accounts and remain visible to others sharing the browser. Do not enter sensitive identifiers. Directory responses can grow with the expert catalog; pagination and per-user fairness should precede large expansion.
10. Centralize structured security logs and alert on repeated denials, 429s, storage failures and unusual mutations. Shared-token logs cannot identify an individual operator. Monitor availability separately; no managed alerting, SIEM, retention policy or incident-response service was provisioned.
11. Python dependencies are version-pinned but do not yet enforce wheel/sdist hashes. Registry/package compromise and undisclosed flaws remain supply-chain risks; consider hash-locked artifacts or an approved package mirror. CI action SHAs and npm integrity protect different parts of the chain. Re-run all scans regularly and review lock changes rather than relying on this dated result.
12. Neither public deployment nor submission has occurred. Existing submission identity/contact limits remain unchanged. Do not represent this audit as external validation, an expert endorsement or a security certification.
